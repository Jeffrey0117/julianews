# julianews

Static multi-page marketing/portfolio website for "Julia" (wedding / dress studio), built with Tailwind CSS v4 CLI + vanilla jQuery.

## Stack
- Plain HTML (15 standalone pages, no framework/router)
- Tailwind CSS v4 via `@tailwindcss/cli` (compiled from `input.css` → `assets/css/style.css`)
- jQuery (`assets/js/jquery.min.js`) for all interactivity in `assets/js/main.js`
- Libraries (vendored, not via npm): Swiper (sliders), flatpickr (date picker), nice-select (styled selects)
- Dev tooling: `live-server` (static server), `concurrently` (run CSS watch + server together)
- No build framework, no TypeScript, no tests, no backend

## Directory structure

```
*.html              ← 15 page files at root (index, gallery, dresses, reviews, story, blog, news, photo, video, styling, overseas, *-details ...)
input.css           ← Tailwind source: @theme tokens + custom component classes (.btn, .container, .title_*, etc.)
assets/
  css/
    style.css       ← GENERATED by Tailwind — do not edit by hand
    custom.css      ← hand-written overrides
    flatpickr.css, nice-select.css, swiper.min.css  ← vendor CSS
  js/
    main.js         ← all site behavior (dropdowns, hamburger menu, swipers, tabs, flatpickr, scroll-to-top)
    jquery.min.js, swiper.min.js, flatpickr.js, nice-select.js  ← vendor JS
    floating-buttons.js
  img/              ← all images/SVGs
  video/            ← video.mp4
```

## Key concepts
- Multi-page static site: each `.html` is self-contained and links to the shared `assets/`. Header/footer markup is duplicated per page (no templating) — edits to shared UI must be applied to every page.
- `*-details.html` pages are detail/sub views (blog-details, dresses-details, review-details).
- Styling is Tailwind-utility-first. Reusable component classes are defined in `input.css` under custom selectors (`.btn`, `.btn.v2/.green/.yellow/...`, `.container`, `.title_1`, `.title_2`, `.text_24/.text_32`). Theme tokens (fonts, transition) live in the `@theme` block.
- Root `font-size` is viewport-scaled (`vw`-based) so the whole layout is responsive via `rem` units.
- `main.js` wires up: responsive dropdown (hover on ≥992px, click on mobile), hamburger menu toggle (`body.menu_active`), Swiper hero + service sliders, jQuery tabs (`[data-tab]`/`[data-tab-content]`), flatpickr date pickers (`#selectDate`, `#selectDate2`), nice-select, smooth scroll to `#contact` and scroll-to-top.
- Fonts loaded from Google Fonts (League Spartan, Noto Sans HK) via `@import` in `input.css`.

## Commands
```bash
npm install        # install dev deps (tailwind cli, live-server, concurrently)
npm run dev        # watch CSS + serve on http://localhost:4000 (concurrently)
npm run css        # tailwind watch: input.css → assets/css/style.css
npm run serve      # live-server only, port 4000
npm run build      # tailwind one-shot, minified output
```

## Coding rules
- Never hand-edit `assets/css/style.css` — it is generated. Change `input.css` (or `custom.css` for overrides) and re-run `npm run css`/`build`.
- Add reusable styles as component classes in `input.css`; use Tailwind utilities inline in HTML for one-offs.
- Since pages share no template, replicate shared markup (header/nav/footer) changes across all `.html` files consistently.
